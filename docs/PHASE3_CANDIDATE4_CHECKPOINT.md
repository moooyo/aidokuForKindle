## Supported cache lease coverage

The native launcher permits one application instance. Reader work and the
download actor open the same canonical cache in that process; the process-wide
registry shares its `Arc<CacheInner>`. `CacheLease` protects managed artifact
identities through this shared in-memory state. It is not a lease protocol
between independent GUI processes.

The [current test-scope record](../artifacts/phase3/candidate4/cache-correctness/unit-scope.json)
binds seven exact successful tests from the actual 448-test output to the same
225-file Candidate4 source. In
`downloads::tests::removing_completed_download_keeps_other_owners_and_active_reader_leases`,
test code holds a genuine `CacheLease` while a separately started download
actor thread opens the cache and removes a completed chapter. The raw file
remains present; after dropping the lease and pruning, the unpinned file is
reclaimed while the other durable owner remains protected. Separate book-removal
tests cover the actor's managed states, shared owners, local imports, failure
compensation, active-transfer drain, and suspend barrier. Cache-clear tests
cover actual leases and reservations under forced reclamation.

Those tests retain their individual scopes. A separate
[five-stage application check](../artifacts/phase3/candidate4/live-reader-lease/run-20261106T101821Z-681323/report.json)
now also passed on the frozen desktop executable. It created a real six-page
provider download, observed the new Reader PID's actual full-viewport X11
pixels and fresh accepted-progress write, and used existing application actions
for whole-book cleanup and forced cache clear. No lease, page, job, or owner
was inserted through SQL.

After the real cleanup actor finalized, all durable owners were gone. Forced
clear actually evicted all five unshown raw siblings while the displayed raw
and processed files retained their original hashes. The final Reader snapshot
reported two leased entries, zero pinned entries, and eleven evictions; every
930-by-1240 Reader pixel matched the processed-artwork oracle with zero ignored
pixels. After that Reader process exited, a fresh non-Reader application clear
reclaimed the remaining two files and reported zero entries, bytes, and leases.
All 58 archived evidence members, including the six executed tools and original
driver log, were copied from the worker with matching checksums.

The live check establishes same-application Reader and worker/manager
protection. The detail/confirmation actions ran before returning to Reader; it
does not claim uninterrupted physical display during those actions. It does
not test or claim a lease protocol between independent GUI processes. This
cache-correctness artifact has zero visual-round credit and supplies no
throughput or latency improvement claim. Production source, frozen executable,
and all six verification-tool hashes remained identical before and after it.
