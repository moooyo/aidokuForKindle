# Frozen release draw sampling contract

Use the unmodified Slint 1.17.1 stock arm of the existing [release Gray8 fixture](../../startup-library-transition-20261122/first-draw-profile/release-gray/README.md). x86-64, release opt level 3, LTO disabled, line-table DWARF and symbols kept. Do not change text, glyph or renderer policies. Observe only the first actual six-book Library draw, not a stock card, a framebuffer operation, a subsequent redraw or an e-ink panel.

- Run **12 independent processes per layout**, alternating which layout goes first in each pair. No replacements or adaptive periods. Keep all failures. Each visit must pass exact physical full damage and canonical Gray8, 2× scale, six books/placeholder assertion, reversible pointer test, clean closure and subsequent draw. Compare every complete canonical frame byte for byte against one fresh unsampled reference per layout. No pixels or raw stack addresses are published.
- First/last `SIGURG` are synchronous thread-directed signals immediately around the measured draw. Only that same process's main thread owns a pinned, non-inherited Linux `cycles` event. It starts disabled and is disabled before the subsequent draw. Sample period **110,000 cycles**, user mode only, monotonic timestamps, 256 KiB ring. Each raw record must be a sample from the captured GUI TID. Lost, overwritten, throttled, malformed or unknown records invalidate the visit. Do not accept hardware events from a background thread. Discard the few samples inside the enabling/disabling signal handlers' uncertainty brackets rather than assigning them to the renderer.
- Require at least **35 retained samples per visit**, at least **80% first-to-last span** relative to the gate's inner clock interval, and samples in each of four equal subintervals. Reject gate/draw duration disagreement above 150 µs or 5% of the uninstrumented draw interval, whichever is larger. Collection/missing/insufficient runs remain visible. Publish category estimates only with at least **10/12 valid visits** and **500 retained GUI samples per layout**. A failed gate doesn't authorize another run.
- Resolve the sampled IP and available reconstructed user ancestors into the ELF's symbol and inline ranges. Return addresses are adjusted separately from the interrupted leaf. Classify each sample once, by explicit concrete stage names; generic inlined memory operations inherit the strongest enclosing recognized stage only. Keep unclassified and externally/unresolvably attributed work visible. Demonstrate the gate on an independently compiled three-region control with distinct before/inside/after functions. Report per-profile sample weights, spread and inline coverage. Do not report inferred Kindle milliseconds or equate this short host profile with optical completion.

## Preflight rejection and final freeze (before any application sample)

The original short-window plan above was infeasible at the worker's **7,000 samples/s** kernel limit: even the minimum 35 samples in a 3 ms frame needs 11,667/s. A separate C control at the proposed period returned 31 `PERF_RECORD_THROTTLE` records. No Aidoku visit was consumed under that version. The kernel settings were not changed.

The fixed replacement uses **2,000,000 cycles**, **48 independent fresh visits per layout** in alternating layout order, four or more accepted samples per individual visit and exact same-frame timing. Publish estimates only if **≥40/48 visits and ≥300 GUI samples per layout** survive. In aggregate **each quartile must contain 10–40%** of eligible samples or the timing distribution is insufficient for the ranking. Record each visit's sample span, all four bin counts and first/last/internal gaps, but do not select for long individual spans or nonempty quartiles: that would disproportionately exclude short frames. No retry/replacement, no adaptive period. Use explicit `CLOCK_MONOTONIC` calls immediately surrounding `RetainedScene::render`, inside both signal gates; report uncertainty/skid, not perfect-cycle ownership. A user-cycle overflow interrupting a kernel instruction is attributed only to `unresolved`, never to user or kernel code. The C control must have **no throttles** at this period and show only the middle C work among its three named regions. The published plan and classifier are frozen before consuming the first application sample. Where results remain ambiguous, report only what is supported instead of changing this freeze.
