# Is the Library painting its paper twice?

**Yes in this fixture; removing that fill did not speed up the first Library draw. Leave the original UI and device installation as they are.** The absolute number of avoided stores is not a measure of bottleneck time. No Kindle was used or reserved for this experiment.

| Profile | Actual full-row white fills: A → B | Gray8 bytes avoided per first draw | Stock / candidate median draw | Median paired draw saving; wins | Median paired entry saving |
| --- | ---: | ---: | ---: | ---: | ---: |
| Scribe (1860 × 2480) | 4,960 → 2,712 | 4,181,280 | 4.375 / 4.492 ms | −0.168 ms; 3/6 | −1.261 ms |
| PW6 (1264 × 1680) | 3,360 → 1,880 | 1,870,720 | 3.638 / 4.609 ms | −0.149 ms; 3/6 | −0.482 ms |

Positive savings mean faster without the page fill. These differences were computed within each pair. Neither layout reached the +1 ms/five-win draw gate; Scribe also missed the entry regression guard. Do not infer that this change makes the Kindle slower. Arm order affected the short host measurements. See the [complete unreplaced schedule, observations and all paired results](result.json).

The [stock counter](stock-census.json) recorded two adjacent sequences of exactly 2,480/1,680 full-width white rows and correctly declined to locate the page from that alone. In the [one-line candidate](candidate-census.json), the remaining groups were precisely `[y=0, 2480 rows]`, `[0, 72]`, `[2320, 160]` on Scribe, and `[0, 1680]`, `[0, 56]`, `[1536, 144]` on PW6: window, status, navigation. Only the interior band disappeared. Each release render saw two signal gates, no overflow. The paired difference, exact two-size geometry and retained band matches distinguish this from discarding the window's background or eliminating both full-height groups. Counters ran in separate untimed launches, not during measured trials.

Both languages and both profiles preserved all bytes across ten retained states. Powering on an e-ink panel or inverting its framebuffer was not tested. The real press produced partial damage of 12,544 / 9,216 pixels; whole-buffer comparison still included all pixels outside that damage. All four dynamic pairs and fourteen normal pairs (including one warmup per profile) passed the pixel and interaction guards. The shared build path was restored to its original bytes.

This is one scheduling-independent candidate: leave the window, damage tracking and content clip alone; remove only `background: Theme.paper` from the root of `LibraryPage`. No shared widget, renderer, register, source or font change belongs in the candidate. The prototype is [one_change.py](one_change.py); it refuses anything other than a prepared, private worker source. Do not interpret an instrumented visit as a timing sample.

## Why count first

`AppWindow` sets its background to `Theme.paper`; its intervening content rectangle has no explicit background. Only `LibraryPage` is instantiated inside that rectangle on a non-booting Library route. The root Library rectangle independently paints the same `Theme.paper` (opaque white by day, `#111` by night). Its children still need their normal stacking and clipping. The stock status bar and navigation occupy different vertical bands. Panels, startup and sleep presentation are above this content; they are not the base paper. If a gradient, a painted parent, a differently colored underlay or a distinct page theme is introduced here in future, removing the page's cover would not be valid merely because one capture matched.

The locked Slint 1.17.1 *target-slice* software renderer fills the dirty window ranges before traversing items (`SoftwareRenderer::render_into_buffer_impl` in `i-slint-renderer-software/lib.rs`, the `fill_background` fallback). Later, `RenderToBuffer::process_rectangle` takes the software path, `process_rectangle_impl` emits a solid span for nonzero alpha, and the vendored `Gray8Pixel::blend_slice` already uses `slice.fill` for fully opaque colors. This avoids per-pixel alpha multiplies, not necessarily a second write. Retained dirty clipping still applies. A full-screen bounding box does not imply that all pixels are dirty: the [prior release fixture](../../startup-library-transition-20261122/first-draw-profile/release-gray/README.md) actually summed disjoint damage and confirmed full frames for these first draws.

At the qualified 2× scale, for Scribe the expected *additional* band is 1,860 × 2,248 rows starting at panel y=72 (4,181,280 bytes); for PW6 it is 1,264 × 1,480 starting at y=56 (1,870,720 bytes). These predictions come from first-frame geometry, not a render duration. The [preload counter](fill_count.c) is armed only by the stock fixture's two `SIGURG` boundaries around the first complete Library draw. It looks for opaque paper `memset` calls of exactly one physical row width, with strictly contiguous addresses. The full-height white run must be unique, then the potential second run must also begin on the exact interior row of that **same buffer**. It prints no absolute addresses or pixels. Other widths, unmatched runs, interrupted patterns, missing gates or unseen inlined stores may not qualify. A matching run on stock is consistent with the geometry; differences on the one-change candidate are required for attribution. The [counter control](test_counter.c) deliberately calls `memset` through a volatile function pointer: two full fills outside the gate must disappear; a gated 32×42 scene and its 32×30 body must give exactly `[[0,42],[4,30]]`.

## Prespecified screen

Use the frozen ordinary-stock application from the [release draw profile](../profile/PLAN.md) in the approved `test-env` Ubuntu workspace and its same cache/CPU policy, after coordinating with the profile owner. Do not modify the global Slint registry. Neither arm uses a signal sampler or preload during any timed or correctness visits. Retain the same real async controller, fonts, scale, six local synthetic books, seven placeholders, ink and reversible filter controls. Compile both state-proof binaries with the *same* [untimed state hook](state_materialize.py), then apply only the one-line product delta to B. The primary clock strictly brackets the vendored `RetainedScene::render`; entry → first complete Library is separate. There is no card release, framebuffer, native power/input fence or optical output in this screen.

`screen.py` checks both geometries with English and CJK in separate untimed control/candidate pairs. It captures the entire retained scene in ten states, not just the most recent dirty region: initial shelf; filter button held; filter menu open and closed; night mode; Settings; return to night Library; day mode restored; selected and deselected Library. The [state walk](states.rs) preserves `ReusedBuffer` for each follow-up, with a real partial paint required. It checks at least one pixel changes per transition and verifies return byte-equality within each visit and across arms for every observed state. This is a day/night, route and software pointer check, not an e-ink inversion, device-sleep or physical pointer claim.

Each profile has **one excluded warmup pair and six alternating measured pairs**, using fresh processes and data. Require full Gray8 bytes equal, reversible button response, at least five faster draws per six and at least **1 ms median paired draw saving on both profiles**, and no more than **1 ms median paired entry-to-Library regression on either**. Stop on a failed operational sample; no replacement, alternate variant or promotion based on a fast subset. Keep an instrumented fill count and CPU profile outside this decision.
