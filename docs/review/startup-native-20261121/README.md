# Repeated opens of the installed Library entry

## Protocol frozen before timing

Compare the independently retained installed control with the **unchanged
post-SEND binary** that passed the ten-pair empty-thumbnail confirmation.
Exclude the rejected November 21 warm revision. Use the same normal launcher
path, indexed document, app home, data directory and existing collection on
both arms. Do not copy or reset books, force a cache miss, request a rescan,
modify the catalog registration or install a second document. No research
options, forced exit, rendering trace or timing probe is added to either app.
The operator temporarily selects only the two Aidoku program files and must
return the observed originals at the end; this is not a permanent rollout.

Use the **real stock Library tile** only if a fresh native view independently
identifies that tab and one unambiguous Aidoku artwork, with a matching guard
at the instant of the click and a bounded way to restore the previous tab and
pointer. A tap and an indexed `file:///mnt/us/documents/Aidoku.sh` request are
different starting events. If the tap is inadmissible, a separately frozen
study may start at the indexed URI request. Never combine origins, subtract
one study's dispatch time from another, or report URI timing as click latency.

Collect reference pictures in a separate control visit. Before measuring,
independently identify the upright, settled Library, count visible populated
slots, and freeze the reference rule. Use one excluded visit per arm followed
by six new alternating pairs in order **AB, BA, AB, BA, AB, BA** (A is control).
Do not silently replace a slow, failed or incomplete visit. Use the device
boot clock for the trigger and framebuffer scans every 75 ms. Report bounds
for visible text and navigation, and for that same screen with all visible
art. Membership must persist at least 200 ms; that confirmation time is not
part of the endpoint. Report per-arm median brackets, per-pair midpoint
savings and their median, and bracket-separated wins separately from midpoint
wins. A sampled transition is not evidence of input readiness, a physical
finger action, optical ink settling, or a cache hit on a particular book.

The warm practical target is 300 ms sooner to visible Library content.
Distinguish a consistent gain (at least five of six pairs faster by midpoint,
at least 100 ms median, no more than 50 ms median regression on the other
endpoint) from a change inside observer resolution. Do not promote solely on
this screen. Require normal process and catalog notification, unchanged
owned and peer state, independent full-body and right-toolbar comparisons,
recovery of the original program tuple, and an owner/token-checked release
before interpreting timings. Preserve any admission, exit or protocol failure
separately. User pixels, book titles, device identifiers, private catalog and
transport details are not public evidence.

## Device preparation

The first preparation attempt stopped before either program was selected or
the tile was pressed. An independent disposable-file check identified the
reason: the Scribe's `/mnt/us` is `fuse.fsp`. Its no-replace rename rejected
an occupied destination correctly, but also failed when the destination did
not exist. Ordinary rename preserved the observed inode; it was **not** used
as a substitute for no-clobber on the installed files.

A separate check bound one disposable file over a second using `mount -o
bind`. The selected file's identity and bytes were visible to the native
services, and `umount` revealed the original file with its inode, metadata
and contents intact. Both probes removed their private artifacts, closed
their SSH connections and released the lease. Neither opened Aidoku or
contributed a timing sample.

Before opening the comparison batch, a separate `tapcheck` verified the
untouched R3 program tuple and exercised one real press on the normal stock
Library tile. Text and navigation appeared at **2.090–2.166 s**; all seven
cover slots appeared at **2.915–2.993 s**. The sampler missed no ticks and
used 1.71% of one core. Normal exit, restoration and an owner/token-checked
release completed at 04:39:20 Asia/Shanghai on November 21. This single
control visit is a check of the measurement, **not** a median or a sample
in the candidate comparison.

## First complete batch: visual check failed

All 16 ordinary stock-tile visits completed, with 12 usable timing traces
and a checked release at 05:06:00 Asia/Shanghai. The independent R3
reference rendered **91%**, while both final pictures rendered **89%**.
The two final bodies and complete right status areas were identical to one
another. Against the older reference, the bodies were identical but the
status area differed by 1,535 pixels (the percentage text and the position
of its adjacent Wi-Fi glyph). This identifies a difference in the displayed
reading, not an independent measurement of battery capacity. The original
full-image criterion failed on both arms; it has not been waived.

The original six pairs are retained and **diagnostic only**. The per-arm
median brackets for text/navigation were 2.238–2.314 s (R3) and
2.232–2.309 s (candidate); for text with all covers, 2.635–2.712 s and

## Prospective repeat

Use a new independent R3 reference, a new full 16-visit run and no samples
from the first run. Put the two independent ordinary full-frame pictures at
the **start** of this run, close in time to the reference, so a change of
displayed charge over the timed series is less likely to confound the
visual check. Then run one excluded warmup per arm and six new AB/BA pairs.
Both pictures still have to match the reference's entire body and right
status area pixel-for-pixel; no clock, battery or wireless pixels on the
right are masked. The stock tile, endpoints, sampler, thresholds, native
exit and release requirements are identical. A further mismatch remains a
failure, not grounds for replacing a case.

The new reference verified the same upright layout (six books, seven visible
cover slots) and closed normally at 05:08:18 Asia/Shanghai. The separate
repeat then stopped **before its first document click**: the stock target
no longer met native admission. Neither an app launch nor a candidate
selection was requested. Closeout could not confirm the original native
state, and the trusted SSH route subsequently became unreachable. This
repeat has **zero timing samples**. Do not retry its tile press. Preserve the
original lease/plan for bounded restoration; see the current recovery status
in the [handoff](../../../HANDOFF.md).

The host retried the same pinned SSH endpoint through 05:22:33, without
sending another click. It still reported `No route to host`; that does not
prove the Kindle suspended. Future, not-yet-frozen batches can reset the
normal inactivity timer while stock is already awake, before transfer and
the first long navigation. This is not a wake command or a persistent sleep
inhibit, and it never runs during timing or recovery. Twelve Linux fixture
tests passed. The failed batch's frozen recovery scripts remain unchanged.
