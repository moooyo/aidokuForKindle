# Indexed entry protection

The lease holder runs `sh guard.sh OP LABEL`. `LABEL` is a 16-character
lowercase hexadecimal directory label, not a credential. The only output is a
short acceptance/refusal marker. Take a new host lease before any device
command. These operations do not acquire, renew or release it.

- `admit` is read-only and needs no staging. It requires the selected stock
  foreground, active power, running window manager/statusbar, supported panel,
  no active reader or peer launcher lock, and expected public entry shapes.
- `capture` runs immediately after the transaction creates its two owned
  directories. It stores original light levels and a private projection under
  `/var/tmp/aidoku-native-LABEL/guard`, once. Both that directory's parent and
  `/mnt/us/.aidoku-native-LABEL` must have a matching `owner`. The raw
  projection must never leave the device.
- `verify` rechecks the entire projection and lights when stock owns the
  platform. It makes no writes and refuses a mismatch.
- `restore` is the same check, but may restore the two recorded light levels
  after stock and the protected projection are verified. No program, catalog
  or registration restoration is performed by this module.

The dedicated `programs` module checks the two mutable Aidoku program leaves
and binds their original bytes for rollback. The guard covers the other
public Aidoku leaves, both WeRead launcher paths, its released 95,137,176-byte
program and two helpers, the shared v1 runtime and leaf-regular stock handler.
The installed WeRead supervisor must be **present**. Public file stamps and
types detect drift within this batch; they are not proofs that all installed
bytes came from a particular release. No hash or user-data traversal is used.
The handler may have a symlinked *parent*: its resolved path, leaf type and
stamps must be stable.

The November 20 BiliComics closeout restored the absent canonical installation,
document spellings, selected sidecars and zero rows at its bounded path. Its
November 21 rollout attempt rolled back before a card click. According to the
owner's `bilicomics-return-rollout-attempt-20261121.txt`, the canonical root
and both document lookups were absent, both selected catalog paths had zero
rows, and the original lease was released at 04:26:52 Asia/Shanghai.
The installed-peer profile was rehearsed offline but is not the current
expectation. Recheck the latest owner note before commencing a batch. If
the owner changes the expected state, or an unexpected file or row appears,
refuse without opening, deleting or replacing it.

Read-only SQLite transactions use the owner-reviewed namespace
`MT:text/x-shellscript`, exact shared handler and command, and ordered properties
for that handler and associations for the handler or MIME. Bounded catalog
queries check only the three projects' entry paths; exact Aidoku and WeRead rows
must have the shell MIME and preserve identity, thumb, modification and size.
Last-access time is intentionally excluded from the stable projection: the
normal Aidoku visit owns its usual access update. The original lighting and
native guard must pass again before private batch cleanup and exact release.
