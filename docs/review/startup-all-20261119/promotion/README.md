## Independent defaults

Use `defaults.py prepare --authority FILE --authority-sha256 SHA --application ELF
--launcher SCRIPT --helper ELF` through `ssh test-env` to freeze a private plan.
The authority names the installed control, three final program hashes, canonical
release source and all six policies (`default_on` or `default_off_optional`).
The operator alone runs `python3 -I runner.py run /absolute/plan.json` from the
private plan directory. A failed operation with an unreleased lease uses this
same runner's `recover` action. Each later batch uses a new owner and token.

The actual indexed document and shared integration remain intact. A temporary,
catalog-handoff-checked launcher bridge selects the baseline or candidate
application home, both independent copies of the private fixture. Both launchers
and executables use their unmodified production bytes and normal startup
arguments. There is no benchmark-only option file. In addition to comparing
the actual program, worker and parent identities, the runner separately asks
the candidate for its six resolved settings and checks the launcher's actual
portrait execution mode. The normal application is not started with the
settings-inspection switch.

Permission and epoch-matched input release, full resume, same-process park/wake,
the cooperative ordinary-exit acknowledgement and the absence of a retained
process are required. The actual catalog item must remain unique and unchanged
with advancing last-access time, exactly one successful native notification,
and matching protected before/after system state and released lease. A raw
full-resolution Scribe P6 is captured both before sleep and after wake on both
sides. The compressed physical captures stay in an owner-checked, root-only
`/var/tmp` directory on the device until transferred to the private test-env
batch; they are never written to the USB userstore. Host replay verifies the
complete image body below the clock, plus the nonuniform right-side Wi-Fi and
battery area, against the independently collected case sidecars. Public reports
contain booleans and geometry, not user pixels, their hashes or device IDs.

`python3 -I defaults.py qualify --batch PRIVATE_BATCH --plan-sha256 SHA
--output FRESH_JSON` replays this qualification entirely on the host. A passing
summary without matching raw observations, collected archives, frozen inputs
and lease evidence does not pass. This does not turn a software input gate into
a physical-tap or optical display measurement. Resident fast return and import
economics have their own physical workflows and acceptance rules.

records four matching raw physical frames across the original and the final

## Package and install

`prepare_all.py` freezes only a complete three-member update: `aidoku/app/aidoku`,
`aidoku/launch.sh` and `aidoku/app/aidoku-startup-portrait`. Every other ZIP/KPM
member, mode and hook must match the installed reference. Each of the six
features must have exercised, separately replayed compatibility evidence.
Unconfirmed optional features are not reported as speedups. The combined final
default also needs its own independent warm and cold regression checks. Neither
the old 62de baseline nor previous single-feature candidates can establish
qualification for the final three-member composition.

For R3, `assemble_r3.py --output FRESH_PRIVATE_DIRECTORY --portrait-pixels
PORTRAIT_QUALIFICATION_BATCH` replays the dated physical campaign and produces
the selection and its digest on test-env. Pass both to `prepare_all.py` with
`--selection`, `--selection-sha256` and
`--source-root /root/aidoku-all-build-20261119/sources/final-v3-clean`.
First run with `--check-only`; use `--output FRESH_RELEASE_DIRECTORY` to
produce the ZIP, KPM, transaction bytes and plan only after the gate passes.
R3 requires the new launcher's own warm and cold guards, native pixels and
ordinary default lifecycle. Resident retention also uses the exact R3
launcher. An earlier isolated import timing trial may contribute on the
byte-identical application with the installed launcher, but R3 still needs
its own import correctness and visual qualification, and the isolated trial
cannot qualify a launch path or the combined default. The separate prewarm
and grace host witnesses exercise the identical compilation inputs and make
no claims about timing or physical R3 frames.

The coordinating operator first uses `python3 -I run_all.py --plan PLAN
--plan-sha256 SHA --operation install-smoke --check-only` on test-env. This
rechecks the original baseline receipt, the selected files, both archives,
allowlisted differences, and the complete generated package verification;
for R3 it also reproduces the release selection. It never takes a lease. Run
without `--check-only` only for an accepted release.
The normal installed Library document is opened with the existing user data
and no test routing. Only the application and firmware perform their normal
logging, navigation checkpoint, cache access and catalog recent-access updates.
The driver streams a stable, read-only SQLite projection of books, chapters,
pages, bookmarks, progress, preferences other than the navigation checkpoint,
source configuration and download state directly into a digest. It does not
write, export or restore any user records. Active transfers or an existing
personal startup override prevent a test of the factory defaults rather than
being cancelled or changed by the acceptance tool.

The transaction acquires the normal app lock, takes an exact copy of only the
selected old files, and atomically replaces them. While the application is
fully stopped, separate snapshots immediately before and after the program
swap hash the actual library and cache-index files and their sidecars. They
also compare a streamed names/modes/inodes/sizes/modification- and change-time
snapshot of the entire raw/processed cache. These stricter comparisons apply
to the installer interval, not the legitimate cache activity of a normal
application launch. A private host copy of the exact old application and
launcher is rechecked against the current 9d92/10432125 rollback identities,
modes and the owner-bound transaction journal. It contains no user data.
Baseline, candidate and
same-process wake captures are transferred privately; their body and right
toolbar pixels are rechecked after releasing the lease. A failed in-batch
smoke first finishes owned native recovery, then restores only installation
files still matching the expected transaction bytes. It never uses an old
catalog or user-data snapshot. A post-release private archive mismatch is
reported as a qualification failure and requires a fresh rollback lease.

For rollback, use the same plan and its hash with `run_all.py --operation rollback
--transaction-run ORIGINAL_RUN`. The original rollback targets are the actual
`9d92dc4c...` application and `10432125...` launcher; the helper is removed only
when this transaction added it and no one has replaced it since. If current
ownership cannot be established, the operator must inspect the private journal.
