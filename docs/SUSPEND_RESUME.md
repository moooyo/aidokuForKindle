# Retained-process sleep and wake

The final C18 targeted Native sequence passed single90 and the final
manual90/270 touch,270 Down/Up and retained flat-wake checks on its actual
ARM35dd/launcher-e4a4 payload. The same final PID6613 retained epoch5/page15 and
manual270, exact wake pixels and unchanged image jobs; normal exit restored the
stock body, policy/USB1 and released App/sensor/guard/locks. See the
[current Native record](PHASE3_NATIVE_RESULTS.md) for precise source identities,
original failed attempts, runtime stage and returned-tree/restore evidence.

Recognized portrait-sensor Up/Down changes active presentation by 0/180 while
preserving page and manual landscape preference. It does not expand manual
four-way choices into automatic four-way rotation. Firmware-VM synthetic sensors
and RAM fixtures are explicit conditions, not physical Kindle or persistent
filesystem acceptance. Automatic brightness remains unimplemented/unqualified.

The launcher binds retained pause/resume acknowledgements to a nonce and sleep
epoch. Stock sleep checkpoints the accepted frame, cancels stale input/network
work, releases the input grab and parks the process. Wake retains the process,
fonts and accepted image and republishes the full RGB scene. A lost retained
process may recover from its durable checkpoint only for the launcher's own
sleep transition; explicit exit and USB takeover do not authorize relaunch.
Deliberately paused downloads remain paused. These mechanisms' actual final
scope is the bounded report above, not a borrowed older full-matrix pass.
